## 1. The Principal Upaniṣads (Mukhya Upaniṣad)

*   **A · Jāgrat (Waking)**: Externalized sensory interaction (*Bahis-Prajña*). In software: Intake, requirements harvesting, acoustic voice distillation. **Zero code write**.
*   **U · Svapna (Dreaming)**: Subtle internal contemplation (*Antaḥ-Prajña*). In software: Architecture diagrams, interface blueprints, schemas. **Zero code write**.
*   **M · Suṣupti (Deep Sleep)**: Unified undifferentiated potential (*Prājña*). In software: Invariant verification, unit test assertions, silence before action. **Zero code write**.
*   **· · Turīya (The Transcendent Fourth)**: Unconditioned pure consciousness (*Amātra*). In software: Manifestation, multi-agent execution, code release.

### B. Chāndogya Upaniṣad (Tat Tvam Asi & Vācārambhaṇa)
*   *Vācārambhaṇa-Śruti* (6.1.4): "All modification is merely a name arising from speech; clay alone is the reality."
*   In Software: Variable names, frameworks, and syntax libraries are transient designations (*Nāma-Rūpa*); the underlying data structures, byte streams, and algorithmic logic are the true substance.

### C. Bṛhadāraṇyaka Upaniṣad (The Unseen Seer)
*   *Dṛṣṭer Draṣṭā* (3.4.2): "You cannot see the seer of seeing; you cannot hear the hearer of hearing."
*   In Software: The witness consciousness (Sākshī) is not an object inside the context window. It is the observing horizon that watches the prompt, the agent, and the code without being consumed by them.

### D. Kaṭha Upaniṣad (The Chariot Parable)
*   *Rathātīta Model* (1.3.3–4): The Ātman is the chariot owner; Buddhi (intellect) is the driver; Manas (mind) is the reins; Indriyas (senses) are the horses; Viṣayas (objects) are the paths.

### 1. Nyāya (Epistemology & Logic — Gautama)
*   **The 4 Pramāṇas (Valid Sources of Knowledge)**:
    1.  *Pratyakṣa*: Direct perception (e.g., exact compiler output, runtime stack trace).
    2.  *Anumāna*: Logical inference (e.g., inferring a race condition from thread timings).
    3.  *Upamāna*: Analogy/comparison (e.g., matching a design pattern to an existing architectural idiom).
    4.  *Śabda*: Authoritative testimony (e.g., official specification documents, standard RFCs).
*   **Software Practice**: When debugging, never assume. Verify the Pramāṇa. Is the bug directly witnessed (*Pratyakṣa*) or loosely inferred (*Anumāna*)?

### 2. Vaiśeṣika (Atomic Ontology — Kaṇāda)
*   **The 7 Padārthas (Categories of Existence)**:
    1.  *Dravya (Substance)*: Database entities, memory addresses, immutable models.
    2.  *Guṇa (Quality)*: Data types, properties, constants, immutability flags.
    3.  *Karma (Action)*: Functions, mutations, side-effect procedures.
    4.  *Sāmānya (Generality)*: Classes, interfaces, abstractions, traits.
    5.  *Viśeṣa (Particularity)*: Unique object IDs, instances, UUIDs.
    6.  *Samavāya (Inherence)*: Essential bindings (e.g., an integer inherently possessing a numeric value).
    7.  *Abhāva (Non-existence)*: `null`, `undefined`, empty states, missing resources.
*   **Software Practice**: Keep Dravya, Guṇa, and Karma strictly delineated in domain-driven design.

### 3. Sāṅkhya (Consciousness & Nature — Kapila)
*   **Dual Principle**:
    *   *Puruṣa*: Pure, unattached, unmoving consciousness (The Witness).
    *   *Prakṛti*: The dynamic, tripartite evolving substrate (*Sattva, Rajas, Tamas*).
*   **Software Practice**: Sākshī is Puruṣa; the running agentic tools, compiler threads, and file writers are Prakṛti. The observer must never confuse itself with the active engine.

### 4. Yoga (Cognitive Restraint & Memory — Patañjali)
*   *Citta-Vṛtti-Nirodha* (1.2): Quieting the whirlpools of the mind.
*   *Saṃskāra*: Every experience leaves an impression. Impressions generate habit patterns (*Vāsanās*).
*   *Kleśas*: The five afflictions (Ignorance/Avidyā, Ego/Asmitā, Attachment/Rāga, Aversion/Dveṣa, Fear of Death/Abhiniveśa).
*   **Software Practice**: In AI agents, hallucinations are uncontrolled Vṛttis. Sākshī prunes prompt context to `< 380 tokens` to quiet the context window and prevent memory rot.

### 5. Pūrva-Mīmāṃsā (Hermeneutics & Discourse — Jaimini)
*   *Vākyārtha*: Analysis of intent through syntactic context, injunctions (*Vidhi*), prohibitions (*Niṣiddha*), and explanatory prose (*Arthavāda*).
*   **Software Practice**: Parsing user prompts with grammatical rigor, discerning mandatory requirements from casual conversational commentary.

### 6. Uttara-Mīmāṃsā / Vedānta (Absolute Reality — Bādarāyaṇa & Śaṅkara)
*   *Adhyāsa*: The superimposition of an illusory perception onto reality (e.g., mistaking a coiled rope for a venomous serpent).
*   **Software Practice**: Bugs arise when a developer projects an imagined system behavior onto real hardware. Debugging is the systematic dissolution of Adhyāsa.

3.  **Madhyamā**: The internal mental formulation into grammar, sequence, and logic.
4.  **Vaikharī**: The physical articulation into acoustic sound waves or written text/code.
